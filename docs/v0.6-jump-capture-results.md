### 为啥 avg_sum 这么低（0.78）

实盘抓的几个例子：
```
2026-05-21 16:15:31  DOWN buy 15 张 @ 0.48
2026-05-21 16:22:58  DOWN buy 3.41 张 @ 0.63 (partial)
2026-05-21 16:36:30  UP buy 15 张 @ 0.11  ← 极低价
```

**底层逻辑**：
- binance 上跳 $15 → 触发 UP buy → 进 0.40-0.50 区间
- 下一秒 binance 下跳 $15 → 触发 DOWN buy → 进 0.30-0.50 区间
- 同一窗口内 UP+DOWN 累积 → mergeable_pairs > 0 → `apply_merge` 自动配对
- avg_sum = up_avg + down_avg ≈ 0.78
- 每对 $1 redeem - $0.78 成本 = **+$0.22 锁定**

## 3. 核心发现：结构性套利 vs 方向预测

### 之前一直在追的"方向 alpha"
- 假设：binance 跳变 → 押对方向 → settle 时赢
- 现实：binance 在 5min 内常常**多次反向跳变**
- 结果：单次方向预测胜率约 50%，**纯方向押注 EV ≈ 0**

### 实际吃到的"结构 alpha"
- binance 震荡时双向 jump 都触发 → 我们两边都拿货
- avg_sum 低于 $1（因为我们用 max_entry_price=0.65 上限 + 只吃一档）
- merge 锁定每对 $1 - avg_sum
- **只要 avg_sum < 1，merge 必赚**

### 为啥 v0.5.x 没吃到这个 alpha
1. **chase qty 100 张 + 走簿**：吃到深档 0.55-0.65 区间 → avg_sum 推到 ~0.96
2. **rebal 强行配平**：rebal 单笔 fee 抵消 merge 利润
3. **chase 30 / rebal 30 配对**：avg_sum 卡在 0.95-0.98 边界
4. **trap zone (pair_health 1.05) 早期**：错配单边残仓 settle 全亏

### v0.6 怎么避开
1. qty 15 + 只吃一档 → avg fill price 更接近 best_ask（不 walk）
2. 无 rebal → 不主动多吃 fee
3. max_entry 0.65 → 强制低价进货
4. jump 阈值 $15 → 频率高，更容易在同窗口攒到 UP+DOWN

## 4. Residual Settle 这另一半为啥也赚

`cash_received` - `merge_pnl` - `merged_pairs × 1` 之外的部分来自残仓 settle：

```
501 对 merge → $501 from merge
$941.55 - $501 = $440 from settle redeem

residual_cost = $703.33 - 501 × 0.78 = $313
settle return = $440
settle profit = +$127
```

**为啥残仓 settle 也正 EV**：
- 残仓都是单边 UP 或 DOWN（jump 只触发一个方向时）
- max_entry_price 0.65 限制 → 进货价不超过 0.65
- 若 settle 赢 → redeem $1
- 若 settle 输 → redeem $0
- 平均买入价 ~0.4（因为大部分时候 jump 触发时该方向 ask 在 0.3-0.5 区间）
- 即使 50/50 胜率：EV = 0.5 × $1 - 0.4 = +$0.10/张

**asymmetric payoff** 是关键：低价买高赔率，即使方向 50/50 也正 EV。

## 7. 风险与未知

### 已知风险
1. **Calm market**：BTC 波动减弱 → jump 频率↓ → merge 机会↓
   - 极端：一天 jump 5 次 → 单方向单笔，merge 不成 → 残仓 settle 主导（更不稳）
2. **单向趋势市**：BTC 一路涨 → 只触发 UP jump → 全单边 → 全靠 settle 押对
3. **Polymarket book 变薄**：流动性下降 → "只吃一档"实际成交 1-3 张 → 利润缩水

### 待量化的事
- 不同 vol regime 下 v0.6 表现（需要跨多个 calm/excited 日观察）
- 哪些时段 jump 频率最高（亚洲/欧美交易时段）
- max_entry_price 调整对 avg_sum 和 hit rate 的影响

### 不该做的
- ❌ 加 SELL exit（会破坏 merge 配对机会）
- ❌ 加 rebal（会主动制造 fee 损耗）
- ❌ 把 FV S 切回 binance（会高估 fair_up 触发错误 chase）

## 8. 教训 & 反思

### 错的判断
1. ✘ "binance 领先 5s 是 alpha 主要来源" —— 实际方向胜率 ~50%，不是 alpha
2. ✘ "chase 用大 qty 30 张抢 alpha" —— 大单走簿推 avg_sum 到 0.96
3. ✘ "rebal 锁 merge 是必要的" —— 反向加重 fee 损耗，无 rebal 反而靠 jump 自然配对效果更好
4. ✘ "FV S 用 binance 更准" —— v0.5.2 错的，导致 chase 选错方向

### 对的判断（v0.6 验证的）
1. ✓ chainlink 作 FV base S
2. ✓ Deribit smile 作 σ 源（虽然不直接决定 trigger）
3. ✓ jump threshold 应该低（$15）
4. ✓ 只吃一档比走簿好（避免推高 avg fill price）
5. ✓ 不强行 rebal 反而能让 merge 自然发生在低 avg_sum

### 设计哲学
- **少即是多**：1 个触发路径胜过 3 个
- **结构 > 预测**：merge 套利是结构性的，方向预测是随机的
- **低 qty 高频**：15 张 × 多次 比 100 张 × 少次 更好（avg_sum 控制）
- **不动 = 最大利润**：hold to settle 比主动 SELL 简单且不破坏 alpha
